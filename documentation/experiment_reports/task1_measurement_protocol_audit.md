# 测量协议审计说明：离线 Q 值与排序测量

审计对象：`scripts/measure_offline_q.py`（数据集层面）、`scripts/verify_local_rank_inversion.py`
（策略访问状态层面）。测量对象为 5m_vs_6m Medium 子集上的冻结离线检查点
`checkpoints/ovmse_paper_5m_vs_6m/ovmse_paper_seed1_best.pt`。

审计方式：只读复算（无参数更新、无环境交互），数据取自 OG-MARL Vault 本地副本。
所有数字均可用上述两个脚本复现；本说明同时给出了修正后的指标口径，两个脚本已按新口径
输出，旧键名以 `*_deprecated` 语义的别名保留，便于和已有结果文件对齐。

## 一、关键发现：+0.93 不是高估，也不全是收缩，而是两件不同的事被混成一个数

**一句话结论**：`Q̄ − G_t` 这个量里含两块性质完全不同的东西——一块是**真实、系统性、正向**的偏移（来源是"critic 评的是另一个策略"加"QMIX 分解自带的上界"），另一块是**均值恰好为零的收缩/噪声**。原报告的 `bias_mean = +0.93` 把前者当成分子、把后者的形状（63% 为正、符号翻转）当成佐证，合成出一个叫"高估"的读数。两块都不是估计误差。

下面用数据把这两块拆开。

### 1.1 一个真实的事例：同一个决策走了 232 次

数据集中有一个 (状态, 联合动作) 组合被前后走了 **232 次**：**192 次在败局**、**40 次在胜局**。
因为输入完全相同，critic 每一次都给出**逐位相同**的分数：

| | 数值 |
|---|---|
| Q̄ 给这一个决策打的分 | **11.85**（232 次完全一致） |
| 这 232 次实际走出来的折扣回报 G_t | **7.17 → 16.65** |
| 只算 192 个败局（G_t ≈ 7.2~10.5） | Q̄ 永远太高：平均 **+3.36**，**100% 为正** |
| 只算 40 个胜局（G_t ≈ 16.4~16.7） | Q̄ 永远太低：平均 **−4.69**，**0% 为正** |
| 这 232 次实际回报的经验均值 | 9.88 → Q̄ 高出 **+1.97** |

同一个 critic、同一个决策、同一个数字 11.85，在败局里 100% "高估"，在胜局里 100% "低估"。
同类决策还有 178 个横跨胜负局；按出现次数排前三的另外两个是 Q̄ = 11.59（经验均值 9.98，
高 +1.61）、Q̄ = 10.86（经验均值 10.08，高 +0.78）。

**这就是"符号翻转"**：不是 critic 时好时坏，是**它报的值不包含"这一局会不会赢"这个信息**，
而数据集记的 G_t 是已经发生的那一个结局。

### 1.2 残差分解：+0.93 一丝一毫都不是收缩贡献的

把残差按"同一个决策"分组做标准分解（时序预测里画 reliability diagram 的同一件事）：

```
Q̄ − G_t  =  [ Q̄ − 该决策实际回报的经验均值 ]  +  [ 该决策的经验均值 − 这一次的 G_t ]
                项1：真实偏移                         项2：纯收缩/噪声
```

| | 均值 | 标准差 | 占总方差 |
|---|---|---|---|
| 报告的 `Q̄ − G_t` | **+0.9282** | 3.356 | 100% |
| 项1 `Q̄ − 该决策的 G 经验均值` | **+0.9282** | 3.013 | 80.6% |
| 项2 `该决策的 G 经验均值 − G_t` | **0.0000** | 1.478 | 19.4% |

项2 按构造就是 0——收缩把高的拉低、把低的拉高，组内加减正好抵消（`var(resid) = var(项1) + var(项2)`，
组内协方差为 0，分解精确）。

**所以：`+0.93` 这个均值全部来自项1，即"critic 给每个决策打的分，系统性地坐在行为策略在该决策
上的平均实际收获之上 0.93"。收缩对均值的贡献严格为零。**

这一点很重要，因为它划清了两种错误读法的边界：

- 说"这是系统性高估" → 错。项1 不是误差（见 1.5）。
- 说"这全是均值收缩，均值应该是 0" → 也错。收缩的均值确实是 0，但观测到的均值是 +0.93，
  说明有一块真实存在的正向偏移。

### 1.3 收缩体现在哪里：离散度和符号结构，不在均值

| 证据 | 数值 | 含义 |
|---|---|---|
| 同一决策 Q̄ 逐位相同的比例 | **13,562 / 13,580 = 99.9%**（差 <1e-9） | Q̄ 是确定性函数，一个决策基本只给一个值，**无法表达"这可能成也可能不成"**；少数例外（最大差 3.11）是量化后的全局状态不能唯一确定历史、GRU 隐状态不同所致 |
| 回合级波动：Q̄ 均值 std vs G_t 均值 std | 2.12 vs 3.44（**0.62 倍**） | Q̄ 把好局/差局压扁了约 38% |
| 仿射拟合 `G ≈ 0.72·Q + 1.16` | 斜率 0.72 | 同样指向衰减/压缩 |
| 同一决策内 G_t 的全距（横跨胜负的 179 个决策） | 最大到 9.5（7.2→16.7） | 单次实现结果的离散度远大于 Q̄ 能表达的范围 |

按结局分档，符号结构非常清楚：

| 回合分档 | 转移数 | 平均 G_t | 平均 Q̄ | Q̄−G_t | Q̄>G_t 比例 |
|---|---|---|---|---|---|
| 最差三分之一 | 40,496 | 4.30 | 6.13 | **+1.83** | 69.4% |
| 中间三分之一 | 46,264 | 4.78 | 6.48 | **+1.71** | 74.9% |
| 最好三分之一 | 48,496 | 10.07 | 9.51 | **−0.56** | 46.4% |

（按胜负切更极端：胜局 −2.11、仅 24.6% 为正；败局 +1.84、74.5% 为正。）

### 1.4 判决性实验：只改样本构成，不改 critic，读数就改符号

同一份 checkpoint、同一个 critic、同一批数据，**只把胜局/败局的权重从实际的 23:77 改成 50:50**：

| 数据集构成 | "偏差"均值 | "高估率" |
|---|---|---|
| 实际 Medium 子集（23% 胜局 / 77% 败局） | **+0.93** | **63.0%** |
| 同样的数据，胜局败局各占一半 | **−0.14** | **49.5%** |
| 假设全是胜局 | −2.11 | 24.6% |
| 假设全是败局 | +1.84 | 74.5% |

**一个估计误差不该因为样本里胜局多两个而改变符号。** 一个真正的单向高估必须在每个子总体里
都为正——这里恰恰相反。所以 +0.93 / 63% 主要测量的是"这份数据集里败局占 77%"这一事实。

### 1.5 那 +0.93 到底是什么：策略差，不是误差

项1 = +0.93 的准确含义是"critic 的分数比行为策略的平均实际收获高 0.93"。这恰好是离线 RL
**应该**有的样子：

- 行为策略整局回报 **12.05**（5,000 局，胜率 0.221）；
- 同一份检查点贪心评估回报 **14.99**（32 局）；
- 差距约 3 个整局回报，摊到每个转移约 0.9——**和 +0.93 同一个量级**。

也就是说，项1 可以被"critic 提取出的贪心策略优于产生数据的行为策略"完整解释。这不是
"估错了自己的目标"，这是"对标错了对象"。

再加上 1.5 末尾的结构性上界，项1 连符号都是被保证的：

> `ovmse/learner.py` 第 151–166 行：自举目标是 `r + γ·mixer(max_i Q_i(s',·))`。mixer 权重过
> `torch.abs`（`qmix/networks.py` 第 96、104 行）是单调的，而各智能体的最大值**分别**取，所以
> 这个自举值是任何可实现的联合动作价值的上界。**即使 critic 训练得完美无误差，
> `Q̄(s_t,u_t) ≥ V^π(s_t)` 对任何策略 π 都成立。**

### 1.6 与时序预测的对应：同一件事，同一套诊断

这个形态在时序预测里极其常见：用平方损失拟合一个含噪目标，模型收敛到 `E[y|x]`，于是必然
**低估峰值、高估谷值**，pooled bias 完全取决于测试集里峰值/谷值的比例。对应的诊断方法三条
照搬到这里全部适用：

1. **绝不报 pooled bias，按结局分位数分层报** → 已加 `q_minus_recorded_return_by_episode_outcome`。
2. **画 reliability diagram**：预测值 vs 同一个 x 的多次实现的经验均值，而不是 vs 单次 y
   → 1.2 节做的就是这件事，结论是 Q̄ 高出经验均值 +0.93。
3. **检查模型的离散度是否匹配结局的离散度** → Q̄ 的回合级波动只有真实结局的 0.62 倍，
   且 99.9% 的决策只输出一个值，**没有任何不确定性表达**。

**但有一处关键差异，正是本审计的核心**：在时序预测里，"预测值高于条件均值"就是**偏差**，
因为目标本来就是条件均值。而这里 critic 的训练目标**不是**"行为策略实际回报的条件均值"——
它是 `r + γ·mixer(各智能体单独取最大)`，评的是它自己的贪心延续。所以"高出行为策略的条件
均值 +0.93"恰恰说明离线阶段成功地提取了更好的策略。

> 用时序预测的话说：这不是"模型有偏"，这是"你在拿一个模型的输出，去对标另一个策略的实际
> 结果"。两边对标错了，pooled 出来的数说明不了任何关于估计误差的事。

### 1.7 由此得到的正确表述

`q_minus_recorded_return_mean = +0.928`（聚类 SE 0.027，t≈34）是**统计显著**的，但它显著地
测量的是三件事的合成：critic 隐式策略优于行为策略（项1 的主体）、QMIX 分解的上界性（项1 的
下限保证）、以及状态粗粒度化导致的收缩（项2 与 0.62 倍压缩）。唯独不是"critic 估错了自己的
目标"。**显著 ≠ 是误差。**

报告中的正确写法：

> 冻结离线 Q 在 63.0% 的转移上高于数据集中记录的行为策略已实现回报，平均高 0.93。该缺口
> 包含 critic 隐式策略优于行为策略这一合法来源（贪心评估 14.99 vs 行为策略 12.05），且在胜局
> 上反向（−2.11、仅 24.6% 为正）；按同一决策分解后，全部均值来自"Q̄ 高于该决策实际回报的经
> 验均值"，收缩项均值为零。因此该读数不能解释为价值高估。

## 三、为什么还可以比、以及能支持什么结论

可以比，是因为两边共享同一个 (状态, 动作) 索引：`Q̄(s_t,u_t)` 和 `G_t` 描述的是**同一
次决策**。这个共同索引让下面三类结论成立：

1. **序数信息存在。** 随机跨状态一致率 0.801、回合内 0.829、τ=0.598，全部远高于随机。
   配合 `verify_observed_joint_rank.py` 的 rank-vs-shuffle 对照（12.36 对 2.42），可以说：
   离线 Q 迁移的是"数据中出现过的联合动作的排序"，而且这个排序携带真实性能。
2. **刻度不保。** 仿射斜率 0.72；同状态 \|ΔQ̄\| 与 \|ΔG\| 相差最多 67 倍。可以说：离线 Q
   **不能**当数值回归目标用，只能当排序用。这与 `da4fc96` 已记录的方向一致。
3. **缺口集中在难配上。** 按 \|ΔG\| 分箱，一致率从 0.53（差 <0.5）升到 0.87（差 >2）。
   可以说：粗粒度上顺序对，近并列上不可靠。

**不能支持的三条结论（原报告越界的地方）：**

- ✗ "离线 Q 存在系统性高估 / 63% 的转移上高估"——见第一节，符号会翻转，且 QMIX 分解自带
  非负缺口。
- ✗ "因此 OVM 的训练目标随之偏高"——OVM 的目标是 `max(Q̄_off(s,a), 在线 TD 目标)`
  （`ovmse/ovm.py` 第 57 行）。要判断它是否抬高目标，必须比较 **Q̄_off 与在线 TD 目标**；
  本测量比较的是 Q̄_off 与**离线行为策略的已实现回报**，两者不是一回事。正的用户策略差恰
  好是 OVM 想要转移的东西。
- ✗ "相邻名次一致率 0.500，所以 argmax 读的是失序"——0.500 的 95% CI 是 [0.13, 0.87]，
  8 个状态支撑不起这个判断。

## 四、排序测量是否把不同状态下的动作直接排序比较？

**`measure_offline_q.py`：是，而且是结构性必然。**

- 代码里配对就是 `rng.integers(0, n, size=(n_pairs, 2))`，在全部 135,256 个填充转移上无约
  束抽样，没有"同状态/同回合"限制。
- 数据侧原因：数据集每个 (回合, 时间步) 只记录**一个**联合动作，而 SMAC 的全局状态虽然高
  度量化（t=0 只有 45 个不同状态，t=5–11 只有 266–625 个），13,576 个不同状态里也只有
  **4 个**记录过 ≥2 个不同联合动作。所以**同状态的动作对在数据集里几乎不存在**，随机配对
  只能跨状态。
- 量化：100 万对随机配对里只有 **193 对**（0.019%）落在同一回合内。而且 G 的跨转移方差
  有 **51.4%** 来自回合间。所以 0.801 主要测的是"Q̄ 知不知道这一局打得好不好"，不是
  "Q̄ 会不会在两个动作里选对那个"。
- 附带问题：`rng.integers` 产生的 (i,j) 与 (j,i) 都会出现，`pairwise_outcomes` 对两者判定
  相同，所以 999,992 对实际只有 499,996 个无序对，报告的 `n_pairs` 把独立配对数夸大了 2 倍
  （已在新口径中拆成 `n_pairs_sampled` / `n_distinct_unordered_pairs`）。

**`verify_local_rank_inversion.py`：否，这一份是对的。** 每个种子的三对都在同一个探测状态
上，基准也是"执行该动作后继续贪心"的分支回报，与 Q̄ 的隐式策略口径一致。它的问题是样本量
（8 个状态）和配对总体与算法不符（下一节），不是跨状态。

## 五、算法实际使用的 ranking pairs 与机制测量的候选动作对是否一致？

**不一致，而且要先分清"当前算法"是哪一个——两个答案不同。**

### 5.1 如果当前算法是 OVMSE（被测量的这份检查点所用的算法）

**OVMSE 根本不用 ranking pairs。** `ovmse/ovm.py` 的 `_ovm_td_loss` 只取**已执行动作**上的
`off_tot = offline_mixer(off_chosen, states)`，然后 `torch.maximum(off_tot, td_targets)`。
没有 argmax、没有成对比较、没有符号。

推论：**排序测量测的不是 OVMSE 消费的东西。** OVMSE 消费的是"已执行动作上的离线 Q 数值"，
对应的测量恰恰是第二节那个口径最含混的 "Q̄ − G_t" 幅度比较。方向正好倒过来：幅度测量的
对象对上了、口径含混；排序测量的口径干净、对象没对上。

### 5.2 如果当前算法是 UOT（`configs/uot_5m_vs_6m.yaml`，`learner_type: uot`）

UOT 的 ranking pairs 由 `uot/neighborhood.py` + `uot/hinge.py` 产生，与机制测量**五个维度
全不同**：

| 维度 | UOT 实际使用（`uot_*` 配置） | `verify_local_rank_inversion.py` |
|---|---|---|
| 候选集 | 3 个锚（冻结贪心、在线贪心、已执行）的 **Hamming ≤2** 邻域内、合法且 ∈ S_off，**K ≤ 8**（`uot_k: 8`） | 探测状态上**全部** 合法 ∩ S_off（实测 117–517 个） |
| 配对 | K 个候选里**所有** C(K,2) 对，且 \|ΔQ̄\| ≥ `uot_margin` 0.1 | 手工 3 对：按 Q̄ 名次取 (1,2)、后半段相邻最高频、(1, 末)；无 margin 过滤 |
| 状态 | 在线训练批次的**在线策略访问**状态（ε-贪心） | 冻结贪心轨迹第 10 步的**一个**状态/种子 |
| 消费的标签 | `sign(Q̄(u) − Q̄(v))`，要求在线 Q 同号且分开 `uot_delta` 0.1 | Q̄ 顺序 vs 分支回放回报顺序；**算法从不使用已实现回报** |
| 有效样本 | 每个填充步一组（~10⁵–10⁶ 组） | 8 个状态 × 3 对 = 24 对，且同组 3 对共享名次排序 |

所以 `verify_local_rank_inversion.py` 的 0.500 / 0.625 **不能外推到 UOT 的 hinge 上**。要测
UOT 真正消费的东西，用 learner 自己已经打点的 `uot_sign_disagree`（`uot/hinge.py` 第 63
行：保留对中 `sign(live ΔQ) ≠ sign(Q̄ ΔQ)` 的比例）——那正是在正确的总体、正确的标签上。

`documentation/joint_order_rehearsal_v1.md` 描述的"离线状态上的序数回放"已被注明不再沿用；
`documentation/neighborhood_return_backup.md` 描述的邻域回报自举在当前代码里没有实现
（`uot/` 只有邻域候选构造，没有 Std 加权自举和 floor 项）。审计范围内只有 UOT 消费排序。
