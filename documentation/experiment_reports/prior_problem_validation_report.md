## 1. 实验目的与待验证命题

仓库 `documentation/experiment_reports/joint_reuse_online_validation_results.md` 记录 Insight A 为本仓库 O2O MARL 分析中**证据最强的一条结论**：一个智能体策略的价值依赖于它的队友；把离线策略与在线策略按智能体拼接时，各部分的收益不能简单相加。

既有证据（如 `insight_af_validation_5m_vs_6m.md`、`extra_cross_arm_runs_20261024.md`）的缺陷是：**同时改变队友与被检视的智能体**，因此无法区分「离线策略本身更好」与「队友构成发生了变化」。本实验的设计目标是消除这一混淆：

- **固定 focal checkpoint**，只改变伙伴行为；
- **配对随机性**（common random numbers）：每个配置从同一 env seed 起步、各自带同种子 RNG，episode 序列与伙伴噪声采样在两个分支间一一对应；
- 在三个在线训练时点（t250k / t1M / t3M）重复测量，检验效应是否随训练阶段漂移。

三个待检验量：

```
J_empty        = R(全员在线策略)                     # 基线，全局共用
J_i            = R(agent i 用离线网络, 其余队友在线)  # 单智能体复用
J_ij           = R(agent i,j 用离线网络, 其余在线)   # 双智能体复用

Delta_i        = J_i    - J_empty                    # 单智能体复用增益
I_ij           = J_ij   - J_i - J_j + J_empty        # 交互项：是否可加
oracle-static  = mean_ck[max_cand J] - max_cand mean_ck[J]   # 自适应选择 vs 固定候选
```

> **判据**：若 `I_ij` 显著非零且方向随训练阶段/seed 变化，说明价值不可加；若 `oracle − static` 显著为正，说明存在自适应选择空间。

### 2.3 探针分支语义（关键）

| 分支 | focal agent 的动作来源 | 队友的动作来源 | 队友噪声 eps |
|---|---|---|---|
| `live` | 在线 checkpoint（贪心） | 在线 checkpoint | 0 |
| `off` | **离线 checkpoint**（贪心） | 在线 checkpoint | 0 |

- `J_empty` 取自任一 focal 的 `live` 分支（全员在线）；分析脚本强制校验 **15 个 focal 的 live baseline 完全一致**（否则直接报 `unpaired live baselines`），实测三 seed 三 checkpoint 全部通过，配对性成立。
- `--eps 0` 表示队友**完全确定性**，因此 `Delta_i` 是「离线策略在无噪声队友下的复用增益」；噪声敏感性需另跑 eps>0。

- **总体**：交互项符号在 seed 间频繁翻转，单个 seed 内部也在 checkpoint 之间翻转。**没有任何一对 (i,j) 在 3 个 seed 上保持同号且显著**——这正是「价值依赖队友、不可加」的表现形式，但同时说明**具体的依赖结构不可复现**。

### 3.6 主表三：最优候选与 oracle 差距

|---|---|---|---|---|---|---|
| seed1 | pair_1_3 (10.864) | empty (14.210) | single_2 (15.804) | single_3 (12.7402) | 13.6262 | **+0.8860** |
| seed2 | pair_1_2 (10.531) | pair_2_4 (14.217) | single_2 (16.245) | pair_2_4 (13.0313) | 13.6643 | **+0.6331** |
| seed3 | pair_1_3 (8.971) | pair_0_2 (12.956) | empty (16.795) | empty (11.9805) | 12.9074 | **+0.9269** |

**跨 seed**：oracle − static = +0.8153（sd 0.1592），seed 值 +0.8860, +0.6331, +0.9269 → **3/3 为正且幅度集中**。

**读数**：

- 最优候选在 checkpoint 之间频繁翻转（seed1: pair_1_3 → empty → single_2；seed2: pair_1_2 → pair_2_4 → single_2；seed3: pair_1_3 → pair_0_2 → empty），**只有 seed1 与 seed2 在终态收敛到同一个 single_2**。
- `empty`（即全在线、不复用任何离线策略）在 seed1@t1M 与 seed3@t3M 成为最优——说明某些训练阶段复用离线策略**纯属负收益**。
- oracle 领先固定最优候选约 0.8 return，但 oracle 需要「知道该 checkpoint 的最优候选」，无法在线获得，且绝对幅度仅相当于 seed1 终态 return 的 ~4.8%。

## 4. 实验结论

### 结论 1：离线策略的复用增益随在线训练推进而系统性衰减 ✅ 方向成立

`Delta_i` 的动态对比中 `delta_0`、`delta_1` 均 0/3 seed 为正，`delta_2` / `delta_3` / `delta_4` 也以负为主；终态 seed3 的 5 个 single 全部为负、其中 4 个显著为负。**任何把离线策略固定拼进在线策略的设计都需要引入时效性衰减或再评估机制**，否则在训练后期会主动伤害性能。

### 结论 2：价值确实不可加（队友条件性成立），但依赖结构不可复现 ⚠️ 部分成立

支持不可加的证据：交互项幅度可达 +2~+4 return（多个格子 CI 显著不含 0），且 3.6 显示最优候选随 checkpoint 剧烈翻转——这排除了「所有 agent 可用同一个离线策略统一替换」这类简单方案。  
但反向证据同样明确：**跨 seed 的交互项 sd 大于其均值，无任何 (i,j) 对在 3 seed 上稳定同号显著**。因此可以断言「价值依赖队友」，但**不能断言「依赖关系具有可学习的稳定结构」**——这与仓库中 `insight_af_validation_5m_vs_6m.md` 等既有报告的方向一致，也提示不应基于单次测得的 best pair 设计算法。

### 结论 3：不存在通用的固定拼接规则 ❌

3 个 seed 的 best_candidate 序列互不相同；`empty` 在两个 (seed, checkpoint) 组合上是最优；终态只有 2/3 seed 收敛到 single_2。基于「某个固定 agent 对该用离线策略」的启发式在本实验数据上不成立。

### 结论 4：自适应选择存在稳定但有限的 headroom ✅

`oracle_minus_static` 3/3 seed 为正（+0.886 / +0.633 / +0.927，均值 +0.815，sd 0.159），是全表唯一在跨 seed 层面稳定的指标。含义：**若能在线判定「此刻该复用哪一段离线策略」，确有正收益**。但需注意两点：

1. 幅度有限——约 0.8 return，占 seed1 终态 return 的 ~4.8%，且 oracle 是事后择优口径，含信息优势；
2. 该 oracle 在本实验中基于 16 个离散候选 + 3 个离散 checkpoint 定义，真实可用候选集更小，实际可达收益只会更小。

### 综合判断

> 实验对 Insight A 的**前半句**（价值依赖队友、不可简单相加）给出**肯定证据**，对**后半句**（依赖结构稳定可复现）给出**否定证据**。
>
> 面向工程落地的表述应是：**队友条件性真实存在且不可被忽略，但它的具体形态随训练阶段与随机种子漂移，
> 因此需要的是在线判别机制，而不是离线固定的拼接先验表。**

## 5. 局限与注意事项

1. **统计功效有限**：每格仅 64 episodes、单 seed；2000 次 bootstrap 的 CI 多数跨 0。单个 (seed, checkpoint, pair) 的显著结果只能作方向性证据，本文所有结论均建立在 **跨 3 seed 的符号一致性** 之上。
2. **仅探测 eps=0**：队友完全确定性。噪声敏感性（eps>0）未测，`Delta_i` 的绝对值不能外推到有噪声伙伴的场景。
3. **仅 5 agent / 单地图 / 单难度**：结论在 5m_vs_6m Medium 上成立，其他规模与难度未验证。
4. **单一离线 checkpoint**：全部复用评估共用 `ovmse_paper_seed1_best.pt`，未检验换用其他离线模型是否改变结论。
5. **绝对 return 口径差异**：探针基线（64 ep / eval_seed 424242）与训练内评估（32 ep）不可直接比较，见 3.3 的提示框；本文只使用探针内部配对量。
6. **探针与训练串行**：阶段 3 在各 seed 的训练之后串行执行，不影响统计正确性，但总时长被拉长。
7. **历史遗留**：同目录 `logs_extra_launcher.out` 记录的是 2026-10-24 另一套 extra-runs 验证，其中 `D_seed1` / `D_seed2_H3-5-10_K4-8-16` 两个任务 **core dumped（exit 134）**；`checkpoints/` 下目前仅保留本实验产物，其余历史实验的 checkpoint 已不在本机。
8. **jax 回落 CPU**：`jaxlib` 未安装 CUDA 版本，离线阶段 jax 相关计算在 CPU 上执行（影响速度，不影响结果）。
