## 3. Insight A：队友条件价值与按 agent 移植

### 3.1 设计

对固定在线版本 t，做完整因子评估：全在线队 `all`、每个单 agent 换成离线参数的 `single_i`、每对 agent 换成离线参数的 `pair_i_j`（5 个 agent 共 16 个配置）。每个配置用一个新的 env（seed 424242）跑 200 局，因此 16 个配置共享同一条 episode 序列（common random numbers）。定义

- 冻结 agent i 的伤害：`g_i(t) = J(all@t) − J(i@off, rest@t)`
- 两两交互：`I_ij(t) = J(off_i, off_j | rest@t) − J(off_i | rest@t) − J(off_j | rest@t) + J(all@t)`

`g_i>0` 表示 agent i 的在线策略对队伍有正贡献；`I_ij>0` 表示两个冻结的伤害是次可加的（重叠），`I_ij<0` 表示超可加（复合）。t=0 是完美零假设（在线参数 = 离线参数），用来检查评估管线本身；随机噪声控制把所有队友固定在离线参数、给其余队友加 ε 均匀噪声，用来检验“队友偏移 → 价值知识失效”的剂量反应。

### 3.2 结果

**t=0 零假设。** 16 个配置的 return 全部是 **12.781**，win rate 全部 0.29，Q̄ 与 Monte-Carlo return 的 Spearman 0.760，归一化 bias +0.074。这说明评估管线没有配置间泄漏，后续差异来自策略本身。

**t=25k：在线策略退化。** 全在线队 return **0.000**、win 0（200 局全部打满 70 步、零伤害），`mean_team_deviation=14.13`，离线 Q̄ 的 bias −13.05（归一化 −0.653）。冻结任意一个 agent 只能把 return 恢复到 0.355–0.552：

| 配置 | return | g_i |
|---|---:|---:|
| all@25k | 0.000 | — |
| single_0 | 0.552 | −0.552 |
| single_1 | 0.355 | −0.355 |
| single_2 | 0.432 | −0.432 |
| single_3 | 0.440 | −0.440 |
| single_4 | 0.383 | −0.383 |

在 t=25k，在线策略处于“全员不动”的退化态；离线教师的 Q̄ 在**这些分布外状态上平均只有 −13.05**（归一化 bias −0.653），而真实 return 是 0——价值误差不是变小，而是从 t=0 分布内的 +1.49（归一化 +0.074）翻成灾难性悲观。单个离线 agent 只能恢复到 0.355–0.552，最好的双 agent 移植 pair_2_3 也只到 1.284（离离线队的 12.78 极远），**协调不是 1–2 个 agent 可替换的**。

**t=50k / 100k：在线策略非单调，移植反而有帮助。** 全在线队 2.708 / 1.543（win 全 0），最好的移植都是 pair_0_1：3.230（+0.522）/ 2.812（+1.269）。t=50k 的 g=[−0.30, +0.16, +0.43, +0.53, +0.32]：只有 agent 0 的在线参数是有害的（冻结它 +0.30），其余 4 个在线 agent 有正贡献；t=100k 的 g 全部为负（−1.25, −0.70, −0.37, −0.48, −0.88），**任何**单个 agent 换回离线都提升，15 个移植全部优于全在线队（最差的 single_2 也高 +0.37）。也就是说，在这两个版本上离线混合队比在线队更会打：谁是“有害队友”随版本整体翻转。价值校准同样失败：D(s)=8.95/24.82，归一化 bias −0.282/−1.208，t=50k 的 Q̄–return ρ 甚至为 −0.385。

**t=250k / 500k / 1M：移植不能恢复离线水平。** 全在线队 6.653 / 6.812 / 7.610；最好的移植是 single_0 6.729（+0.076，噪声内）/ pair_1_4 6.633（−0.180）/ single_4 7.608（−0.001）。全部 15 个混合队仍在 6.14–7.61，离离线队的 12.78 差 5.2–6.6；把 1–2 个 agent 换回离线参数最多只能追平在线队，不能恢复离线水平。最差的移植是 pair_2_3 6.139（−0.514）/ pair_1_3 6.200（−0.612）/ pair_1_3 6.155（−1.455），说明错误的移植会显著伤害协调。

|---|---:|---|---|---|---:|---:|---:|
| 25k | 0.000 | pair_2_3 1.284 (+1.284) | single_1 0.355 (+0.355) | −0.552, −0.355, −0.432, −0.440, −0.383 | nan（return 方差 0） | −0.653 | 14.13 |

t=1M 的完整 16 配置显示：agent 4 的冻结几乎无影响（single_4=7.608 vs all=7.610），agent 1 的冻结伤害最大（g=+1.236），冻结 agent 1+2 的组合进一步掉到 6.351。这与“不同 agent 对协调的边际贡献不同”一致。

交互项方面，t=25k 与 t=50k 的 10 个 `I_ij` 全为正（t=25k +0.058 到 +0.435，t=50k +0.261 到 +0.765），t=100k 除 pair_2_3（+0.012）外全部为负（−0.924 到 −0.152）：同一对 agent 的交互在相邻版本之间从次可加翻成超可加。t=250k 的 `I_ij` 在含 agent 0 的对上为负（−0.026 到 −0.212），在不含 agent 0 的对上为正（+0.059 到 +0.258）；t=500k 的 10 个对全部为正（+0.111 到 +0.565）；t=1M 时 {1,2,3} 之间的对为 +0.758 到 +1.041，含 4 的对为 −0.088 到 +0.268。含 0 的对在 250k 为负，说明 agent 0 单独冻结几乎不伤（g_0≈−0.08），但和另一个冻结组合时伤害超过两者之和——这是一个可观测的**超可加交互**，也是“按 agent 独立评估/合并”会漏掉的结构。把 7 个版本两两比较（21 对），`g_i` 的跨版本 Spearman 为 0.00–0.90（中位数 0.50），`I_ij` 为 −0.54 到 +0.87（中位数 0.49）且符号会翻转：**agent 级边际贡献有中等稳定性，两两交互结构则随版本漂移，不能复用**；250k/500k/1M 三个相邻版本内部的 `g_i` 相关仍为 +0.30/+0.50/+0.70，而 `I_ij` 只有 +0.12/+0.13/−0.35。

| 0.05 | 9.227 | 0.03 | 2.00 | 0.657 | +0.064 |
| 0.10 | 7.720 | 0.00 | 3.67 | 0.478 | −0.021 |
| 0.20 | 6.266 | 0.00 | 6.33 | 0.279 | −0.185 |

这是很干净的剂量反应：队友偏移越大，Q̄ 与真实回报的排序相关性越差，bias 从乐观（+0.064）翻成严重悲观（−0.612）。t=250k 的自然偏移（D=6.57、ρ=0.311、bias=−0.062）落在 ε≈0.2（D=6.33、ρ=0.279、bias=−0.185）附近，两条独立扰动路径给出了量级一致的结论；t=50k 对应 ε≈0.3 一档，而 t=100k（D=24.82、bias=−1.208）已经比最大的随机剂量 ε=0.5（D=13.23、bias=−0.612）还要偏离——自然训练轨迹可以把策略带到随机噪声都覆盖不到的分布外区域。

### 3.3 判读

- **支持 Insight A**：价值是队友条件的；移植收益的符号本身随版本改变（50k/100k 冻结 agent 有正收益，250k 之后转为中性或负收益），但任何版本、任何 1–2 agent 移植都恢复不到离线水平，存在可观测的两两交互（含 agent 0 的负交互，且交互符号在 50k/100k 间翻转），随机噪声控制给出单调的价值失效曲线。
- 对算法的含义：OVM 的“离线价值下界”只在离线队友/行为分布内可信；在线队友一旦偏移，Q̄ 会同时出现排序失效和符号翻转。把离线 Q 当作一个固定锚点（而非按当前队友/版本重新校准的提议）在 100k（Q̄ 严重悲观、移植有益）和 1M（移植中性/负、Q̄ 略悲观但排序很弱）会给出不同甚至相反的方向；“移植谁”必须按版本重新测，不能沿用早期排序。
- 局限：本批 7 个版本的 A 运行没有保存 per-episode return，因此无法给配置间差异做配对 bootstrap；配置间 spread 为 0.43–1.45，单个 g_i/I_ij 的显著性不足以逐项下结论，但“所有混合队比离线队低 5–6 点”是稳健的。跨臂批次（`extra_cross_arm_runs_20261024.md`）的 A 运行已保存每配置 200 局的 return，可对 t=1M 的移植差做配对区间。seed 2 与 `all@off` 基线仍是下一步。

## 4. Insight B：版本条件的随机化偏好验证

### 4.1 设计

固定在线版本 π_v，每个验证 episode 最多产生一个 trial：第一个离线教师联合贪心动作 `a_off` 与在线联合贪心动作 `a_v` 不一致的状态视为决策冲突。在冲突步随机执行

- `D=1`：执行 `a_off`，之后继续用 π_v；
- `D=0`：执行 `a_v`，之后继续用 π_v；

`P(D=1|x)=p=0.5`。记录从冲突步起的折扣回报 G，逆概率加权

`Y = D·G/p − (1−D)·G/(1−p)`

是 `τ_v(x)=E[G(a_off;π_v)−G(a_v;π_v)|x]` 的无偏估计，且只用到决策时可得的信息，可以作为在线标签。脚本另用 5 折交叉拟合的 Ridge 响应模型 `τ̂(x)`（特征含 alive 数、phase、不一致 agent 数、Q_off/Q_on 的 margin 与绝对值），并报告置信门（保留 |τ̂| 最大的 q 比例）的效果。教师与在线网络的 RNN 历史都条件在**实际执行的动作**上（这是本轮修复的一个关键 bug；修复前教师历史被错误地条件在反事实动作上，会把教师效应系统性低估）。

### 4.2 结果

| 版本 | trials | 冲突局 | 教师效应 [95% CI] | τ̂ 均值 | τ̂>0 | ρ(τ̂,Y) | ρ(−Q_on margin,Y) | AUC τ̂ | AUC Q_on | AUC Q_off | 置信门 q=0.25 | q=0.5 |
|---|---:|---:|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 25k | 1500 | 1500 | **+1.607** [+1.461,+1.759] | +1.599 | 0.999 | +0.160 | −0.161 | 0.563 | 0.438 | 0.590 | +2.539 | +2.087 |

### 4.3 判读

- **支持 Insight B**：教师偏好随版本翻转且非单调：25k 强正（在线策略退化，教师救场），250k 中性偏负，500k 正，1M 显著负。任何“固定离线教师权重”的 OVM/UOT 方案都会在某一段版本上推错方向；必须按版本在线验证。
- **在线 critic 的置信度不可作为门控**：`−Q_on margin` 对已实现收益的 Spearman 为 −0.161/−0.008/−0.006/+0.036，AUC 0.438–0.528；25k 甚至是反相关（critic 越自信，教师动作越好）。这直接反驳了“用 critic 的 Q 差做置信加权”的常见做法。
- **可学习的响应模型有弱但可用的信号**：τ̂ 的 AUC 0.477–0.563，逐 trial 符号预测很弱；但按 |τ̂| 保留 top 25% 后，版本级效应被放大 1.5–3 倍（250k −0.454、500k +0.517、1M −0.339），且区间不含 0。也就是说，**置信门适合选“在哪里验证/干预”，不能替代验证本身**。
- **冲突广度（n_disagree）是更有结构的候选门控，但不是通用门控**：5-disagree 子集在 arm A 的 25k/250k/500k 显著为正（+1.71/+1.11/+1.26），1M 不显著（+0.28）；1–4 子集在 1M 全为负。它的符号在跨臂后翻转（arm D 1M 的 5-disagree 为 −0.98，arm B 1M 的 3–4 为正），因此可以把它作为“候选验证区域”，仍必须在目标臂/版本上做随机化 trial 确认。
- 对算法的含义：OVM 的教师项应是一个“按版本验证过的提议”，而不是固定下界；可以在冲突状态上用随机化 trial 估符号，再用响应模型把验证结果外推到相似状态。这正好对应 Insight B 的“policy-version-conditioned verification”。
- 局限：单 seed、单地图；τ̂ 是同一版本内交叉拟合，跨版本迁移未测；1500 次 trial 的版本级 CI 约 ±0.2，250k 的 −0.104 本身不显著，但“符号随版本翻转”是显著的。

## 5. Insight C：中心化关系 decoder 是否必要

### 5.1 设计

用离线数据做一步动态预测：输入当前 `(z_i, a_i)` 与全局 state，预测下一状态的四组量——敌方血量（6 维）、敌方相对位置增量（12 维）、友方血量（5 维）、团队奖励（1 维）。三个模型：

1. **加性**：每个 agent 一个 encoder+head，输出求和；无任何跨 agent 项。
2. **中心化无显式 pairwise**：agent encoder + sum/max pooling + 全局上下文，再逐 agent 输出。
3. **中心化 + 显式 pairwise**：在 2 的基础上对所有 i<j 加 pairwise MLP。

80/20 按 episode 划分训练/测试；目标标准化后报告 R²。交互诊断用 2×2 残差

`interaction(j,k) = g(a_j', a_k') − g(a_j') − g(a_k') + g(a)`

加性模型按构造严格为 0；另外报告 `interaction / single_action_effect` 的比值。

### 5.2 结果

| 模型 | 参数量 | enemy health | enemy xy Δ | ally health | team reward |
|---|---:|---:|---:|---:|---:|
| 加性 | 41,496 | **0.9838** | 0.6198 | **0.9715** | **0.8506** |
| 中心化无 pairwise | 107,416 | 0.9799 | 0.5939 | 0.9700 | 0.8485 |
| 中心化 + pairwise | 173,208 | 0.9820 | **0.6496** | 0.9690 | 0.8499 |

交互诊断：

| 模型 | enemy health | enemy xy Δ | ally health | team reward |
|---|---:|---:|---:|---:|
| 加性 interaction | ~2e-8 | ~1e-8 | ~2e-8 | ~3e-8 |
| 中心化 + pairwise | 0.0068 | 0.0112 | 0.0062 | 0.0085 |
| interaction / single | 0.142 | 0.174 | 0.213 | 0.063 |
| 中心化无 pairwise interaction | 0.0074 | 0.0114 | 0.0075 | 0.0085 |

### 5.3 判读

- **不支持“必须中心化关系 decoder”的预测前提**：加性模型在 4 个目标中的 3 个上等于或略优于 4.2 倍参数的中心化模型；显式 pairwise 模块只把最难预测的 enemy-xy 从 0.620 提到 0.650（+0.030），代价是 4 倍参数和 3 倍训练时间。pairwise 交互确实非零，但相对单动作效应只有 0.06–0.21，且没有转化为可观测的预测增益。
- 中心化“无 pairwise”与“有 pairwise”的交互残差几乎相同（0.0074 vs 0.0068 等），说明这里的交互主要来自共享状态上下文和非线性 pooling，而不是显式的两两模块。
- 对算法的含义：在 5m_vs_6m Medium 这一步动态任务上，**不要用“队友交互存在”作为上大关系模型的理由**；关系结构的价值必须在决策层（return/sample efficiency）证明，而不是 next-state R²。
- 局限：只测了一步动态，没有测 value/policy 层面的收益；目标以可加的血量/位置为主，可能低估“集火/包抄”这类高阶交互；需要 decision-level 对照（见第 10 节）。

## 6. Insight D：H 步目标的多模态、实现多样性、持续性与可达性

### 6.1 设计

对每条离线 transition，取 H 步后的状态差 `Δφ = φ(s_{t+H}) − φ(s_t)`，用 KMeans 量化成 goal `g`；φ 含友/敌血量、相对位置、存活数、友–敌距离（30 维）、友–友距离（10 维），共 75 维。状态本身用 64 个 KMeans bin 粗分。测量：

- 动作信息：`H(a|s) − H(a|s,g)`（按 agent 分解后加权）；
- 实现多样性：每个 (state_bin, goal) 内联合动作频率 ≥10% 的不同动作数；
- 回报方差：`(state,goal)` 组内方差 / 总方差，并与**只用 state bin** 的组内方差对比；
- 持续性：相邻步 goal 相同的比例、chance、Cohen's kappa；
- goal 级：support、覆盖的 state bin 数、H 步 return、Δ 血量/存活、可达性宽度。

### 6.2 结果

| H | K | H(a\|s) | H(a\|s,g) | 信息 (nats) | 实现数 | 组内方差 share (state,goal) | 仅 state share | 方差降幅 | kappa |
|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 5 | 4 | 1.346 | 1.291 | 0.054 | 1.22 | 0.254 | 0.283 | +10.1% | 0.300 |
| 5 | 8 | 1.343 | 1.234 | 0.109 | 1.81 | 0.233 | 0.282 | +17.4% | 0.146 |
| 5 | 16 | 1.338 | 1.180 | 0.159 | 2.79 | 0.217 | 0.279 | +22.3% | 0.078 |
| 10 | 4 | 1.228 | 1.160 | 0.068 | 1.28 | 0.318 | 0.350 | +9.1% | 0.395 |
| 10 | 8 | 1.228 | 1.092 | 0.136 | 2.34 | 0.281 | 0.352 | +20.4% | 0.268 |
| 10 | 16 | 1.222 | 1.045 | 0.177 | 2.98 | 0.256 | 0.346 | +26.1% | 0.088 |

goal 级结构（H=5, K=8）：8 个 goal 中 7 个的 support 为 0.057–0.205、覆盖 37–56 个 state bin、H 步 return 1.85–2.68、平均击杀 1.1–1.3 个敌人；剩下 1 个 goal 只覆盖 4 个 state bin、support 0.057、return 0.23、几乎不击杀——这是“闲置/早死”模式。H=10, K=8 的结构相同：1 个 goal 只有 5 个 bin、return 3.76，其余 7 个 return 3.88–5.64。**goal 空间的主轴基本是“未来 H 步能击杀多少敌人/是否发生交战”，而不是丰富的策略意图。**

### 6.3 判读

- **部分支持**：`(state,goal)` 比 state 多解释 9–26% 的回报方差，且每个状态-目标下有 1.2–3.0 种显著不同的联合动作实现——多模态是存在的。但 goal 带来的动作信息只有 0.05–0.18 nats（4–14%），远不足以“决定”动作；goal 更像是回报/交战强度的粗标签。
- **持续性–精度权衡**：K=4 的粗 goal kappa 0.30–0.40，比较稳定；K=16 的细 goal kappa 只有 0.08–0.09，几乎是每步重采样。想要信息量更大的 goal，就失去时间持续性。对算法而言，**粗粒度、H 步、可持久的 goal 比细粒度 plan library 更现实**。
- 对算法的含义：可以把 H 步 goal 作为一个**辅助潜变量/辅助头**（例如给 value 或 policy 增加 goal-conditioned 输入），但不应假设它能唯一决定动作或替代 state; 目标级 support 高度不均衡（一个“闲置”goal 只有 4–5 个 bin），采样时需要按可达性/覆盖度重加权。
- 局限：goal 由 Δφ 的 KMeans 定义，语义受特征尺度影响；没有做 goal-conditioned 策略的在线收益实验（见第 10 节）。

## 7. Insight E：回放选择应按“短期学习增益”而非 TD/density/return

### 7.1 设计

固定一个 learner 快照 θ_0，对每个经验组 j 从同一 θ_0 做**完全相同**的 M 次更新（相同 batch 大小、优化器状态、混合比例），得到 θ_j^+，在同一个 fresh env（seed 424242）上评估：

`U_v(j) = J(θ_j^+) − J(θ_0)`.

组为 TD-error top 25%、状态密度 top 25%、episode return top 25%、随机 25%（N=5,000，故每组 1,250 局）。TD 分数按版本 θ_0 重新计算；density/return 是静态的。两个版本（250k、1M）× 两个预算（100、500 updates）× 64/128 局评估。为区分“更新本身造成的遗忘”和“数据选择的质量”，另跑了 lr=1e-4、200 updates 的温和控制。

### 7.2 结果

**M=100 updates（128 局评估）**

|---|---:|---:|---:|---:|---:|---|
| 250k | 6.670 | −1.970 | **−1.348** | −2.466 | −1.430 | density（比 random +0.082） |
| 1M | 7.548 | −6.179 | **−3.378** | −5.800 | −4.853 | density（比 random +1.475） |

**M=500 updates（64 局评估）**

| t | θ0 return | TD | density | return | random | 最好组 |
|---|---:|---:|---:|---:|---:|---|
| 250k | 6.707 | −5.853 | −4.856 | **−3.600** | −5.140 | return（比 random +1.541） |
| 1M | 7.659 | −5.663 | −6.164 | **−4.934** | −5.966 | return（比 random +1.032） |

**lr=1e-4、M=200 updates（128 局评估，温和控制）**

| t | θ0 return | TD | density | return | random | 最好组 |
|---|---:|---:|---:|---:|---:|---|
| 250k | 6.670 | −1.288 | **−1.098** | −1.170 | −1.932 | density（比 random +0.834） |

### 7.3 判读

- **不支持“某个代理能稳定选出高增益数据”**：全部 24 个单元格里 U 都为负；在 lr=1e-3 的 4 个（版本 × 协议）单元里，TD 有 3 次低于 random、从未最佳；在 lr=1e-4 的 2 个（版本）单元里，三个结构化组都优于 random，但最优代理从 density（250k）翻成 TD（1M）。若代理真的对齐学习增益，至少应看到跨版本/跨预算的排序稳定性，实际没有。
- **一个重要的机制解释**：所有 U 为负，说明在 32 局窄 batch 的固定预算下，**任何** top-quartile 子集都会造成遗忘/过拟合，U 只是在排序“伤害大小”。这不等于“回放选择无用”：温和协议（lr=1e-4、200 updates）下三个结构化组一致优于随机（+0.64 ~ +3.26），说明数据选择确实有信号；但它也说明当前协议没有进入“正增益区”，无法测到正向的 U。若把 lr 再降或把组与随机/在轨数据混合，可能看到正 U；这属于下一步，而不是本轮结论。
- 对算法的含义：不要用 TD-error 作为 replay priority 的唯一/主导信号；如果要用，至少与随机/在轨数据混合，并监测“窄化”导致的遗忘。Insight E 的原始主张（用 U 标签选数据）在测量上是对的，但当前最便宜的代理都失败。
- 局限：32 局/组的 batch 很小，U 的方差大；64 局评估的 return SE 约 0.5，组间 0.2–0.8 的差异只能看方向；单 seed、单地图。

## 8. Insight F：采集价值 B 与教学价值 T 不是一回事

### 8.1 设计

三个采集者 z：离线教师、online-250k、online-1M。每个采集者在同一 seed 515151、ε=0.05 下采集 48 局，得到等预算数据。两个学生快照：离线教师、online-250k。对每个（采集者, 学生, 预算）从同一学生快照做固定次数的更新，在 seed 424242 上评估 64/128 局：

`B_v(z) = J_v(π^z)`（采集者自己的贪心表现）  
`T_v(z) = J_v(student after z) − J_v(student before)`.

先跑 lr=1e-3、预算 100/300（与在线训练同 lr），发现离线学生会被 Q 尺度差击穿；补跑 lr=1e-4、预算 30/100 的温和协议。

### 8.3 判读

- **方向支持 Insight F，且教学价值依赖学生**：对稳定的 online-250k 学生，B 和 T 的排序在激进协议（预算 30/300）和温和协议（lr=1e-4、预算 100）下都反向（Spearman −0.5 / −1.0 / −1.0）；最高 B 的离线数据（12.76）是最差的教师（温和协议 T=−0.185，激进协议 T=−1.44 ~ −3.46），而学生自己的 on-policy 数据是伤害最小的（T=−0.070 ~ −0.21）。同一批数据对离线学生却给出**一致**的 B/T 排序（+1.00，离线数据最好）。因此“采集者表现好”不等于“它的数据适合教当前学生”；T 必须相对具体的学生 v 来定义。
- **一个必须写清楚的测量伪影**：离线学生的 Q 值尺度显著更大（Q̄ 均值 3.36、max 15.2，而在线 checkpoint 约 1.2/6.8），在 lr=1e-3 下前几十次更新就把策略推离原分布，return 直接归零（T=−12.699）。这不是“离线数据没有教学价值”，而是 Q 尺度失配 + 高 lr 的灾难性遗忘。lr=1e-4 把离线学生的伤害从 −12.7 降到 −1.9 ~ −3.5，但仍然是负的；因此离线学生的 T **只能用于同一学生内的相对排序**（它与 B 一致），不能与 online 学生的 T 混在一起比较。
- **所有 T≤0**：48 局数据、固定预算下，学生从未获得正收益，实验测到的是“哪种数据伤害最小”。这不否定 B≠T，但说明“教学价值”的绝对水平需要更大的数据预算或更合适的学生初始化才能测到正值。
- 对算法的含义：如果为蒸馏/教学采集数据，优化目标应是 T（学生经过训练后的增益），而不是采集者的 J；高 B 的离线数据可能因为状态分布/队友上下文不匹配而成为坏教师。这与 Insight A/B 的“队友/版本条件”一致。
- 局限：单 seed、单地图；采集预算 48 局偏小；离线学生的 Q 尺度问题需要一个显式的尺度归一化/更低 lr 的协议；温和协议的 1M 采集者和 online 学生结果待补。

## 9. 对 O2O 算法设计的合并含义

1. **价值必须按队友和版本条件化（A+B）**：离线 Q̄ 在 t=0 与真实 return 的 ρ=0.760，但到 250k/500k 只有 0.31/0.23，1M 只有 0.11；随机队友噪声把 ρ 单调压到 −0.21。归一化 bias 同时从 +0.074 翻到 −0.65（25k）；在最需要教师纠正的退化状态上 Q̄ 平均只有 −13，远低于已实现回报，OVM 的 `[Q̄_off − y]_+` 在那里完全不激活。也就是说，离线价值只有在离线队友/行为分布内才是可用的下界提议；队友一变，它要么失效（hinge 不触发），要么在排序错误的区域给出方向错误的 lift。
2. **教师偏好需要在线、按版本验证（B）**：同一离线教师在 25k 是强正（+1.61），250k 中性（−0.10），500k 正（+0.33），1M 负（−0.21）。固定教师权重/固定 λ 的 OVM/UOT 调度无法覆盖这个符号翻转；更合理的结构是“冲突状态随机化 trial → 估 τ_v → 响应模型外推 → 只在置信区域使用教师”。
3. **critic 置信度不是可靠的教师门控（B）**：`Q_on(a_v)−Q_on(a_off)` 与已实现收益几乎无关（AUC 0.44–0.53），25k 甚至反相关。不能用 critic margin 给教师项加权；critic 的 margin 只能表示“它有多坚持自己的动作”，不表示“它有多正确”。
4. **不要为关系 decoder 预付 4 倍参数（C）**：在 5m_vs_6m 的一步动态上，加性模型已经吃掉 0.98/0.62/0.97/0.85 的 R²；pairwise 交互存在但小（0.06–0.21），且没有转化为预测增益。关系结构的价值要在决策层证明。
5. **goal 只适合做粗粒度辅助变量（D）**：0.05–0.18 nats 的动作信息、9–26% 的方差降幅、1.2–3.0 种实现，配上 kappa 0.08–0.40 的持续性——足以做辅助头/重加权，不足以做“目标决定动作”的强假设。
6. **回放选择有信号但代理不稳定（E）**：温和协议下结构化子集一致优于随机，说明“选数据”不是伪命题；但 TD/density/return 的最优排序随版本和预算翻转，TD 在高 lr 下 3/4 次低于随机。若要用优先级，至少保留随机/在轨混合，并把“更新后 return”作为在线监控，而不是把 TD-error 当作增益的代理；更要紧的是先用 U 标签在目标版本上校准代理，而不是跨版本复用排序。
7. **采集与教学分开评估（F）**：B 最高的采集者可能是 T 最差的教师；为蒸馏采集数据时，应该用目标学生的 T 做选择，且注意学生 Q 尺度与 lr 的匹配。

## 10. 局限与下一步

- **A**：保存 per-episode return 以做配对 bootstrap；补 seed 2、`all@off` 基线；把“移植后 Q̄ 的排序”与“移植后真实 return”直接对齐，检验 value 是否能预测移植效果。
- **B**：seed 2、更多 trials；把 τ̂ 在版本间做迁移测试（用 250k 拟合的模型去预测 500k）；在线 pilot：只在 τ̂ 置信且符号为正的冲突上执行教师动作，测 return/win 的配对增益。
- **C**：decision-level 对照——用加性 vs 关系 decoder 初始化 value/policy，在相同预算下比较 return 和 sample efficiency；加入“集火/包抄”类的定向探针。
- **D**：goal-conditioned 策略 pilot（goal 作为辅助输入/辅助 loss），比较 sample efficiency 与 mode coverage；用可达性/覆盖度重加权，处理“闲置 goal 只有 4–5 个 bin”的不均衡。
- **E**：把更新放到正增益区（更低 lr、更大 batch、与随机/在轨数据混合），保存每个 θ_j^+ 以便用 200+ 局重新评估；3 seeds；报告 U 的配对 CI，而不只是均值排序；把 U 标签与代理排序做逐版本校准，而不是跨版本复用。
- **F**：统一学生协议（低 lr、Q 尺度归一化，或从共同初始化开始），补 1M 采集者与 online 学生的温和结果；增加采集预算（48 → 200 局）看 T 是否转正；把 T 的排序与 B 的排序在 3 个采集者上做正式的 rank 检验。
