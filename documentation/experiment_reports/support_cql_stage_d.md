# 队友支持度门控（TCVM）阶段 D：保守项放置的受控训练验证（5m_vs_6m）

日期：2026-10-28。运行脚本：`scripts/run_support_cql_stage_d.sh`；分析脚本：`scripts/analyze_support_cql_stage_d.py`。

本阶段在阶段 C 放弃价值记忆通道之后，把同一个已验证的队友支持度信号换到**保守项（CQL）加权**通道上，检验"在哪里施加保守惩罚"是否影响在线适应效果。

## 1. 实验设置

同一离线检查点 `checkpoints/ovmse_batch_20261014/5m_vs_6m_offline/ovmse_paper_seed1_best.pt` 出发，4 臂 × 3 seed，每条在线微调 20 万步。配方、预算、探索调度、评测种子（424242）与阶段 C 完全一致，唯一区别是在线 CQL 惩罚的放置方式：

| 臂 | 含义 | 开关 |
|---|---|---|
| `nocql` | 不施加在线保守项 | `online_cql_weight=0` |
| `uniform` | 全局均匀保守项 | `online_cql_weight=50.0`，`support_cql_mode=off` |
| `gated` | 保守项按队友支持度门控放置：老队支持高的步多罚 | `support_cql_mode=on`，`online_cql_weight=50.0` |
| `anti` | 同一门控取反：老队支持低的步多罚 | `support_cql_mode=anti`，`online_cql_weight=50.0` |

`uniform` 是严格的等质量对照：CQL 损失以加权均值归约，改变权重只改变惩罚位置，总质量固定为 `online_cql_weight`。因此若 `gated` 优于 `uniform`，才能说明"放在老队支持高的步"这一放置策略本身有用；`anti` 作为反向放置，用于判断信号方向。

θ 仍由离线数据自身偏离分位数标定，三个 seed 得到 θ = 1.2149 / 1.2149 / 1.2149，温度 0.1229 / 0.1229 / 0.1229。

## 2. 主结果

尾段均值取最后 3 个评测点（约 17.2 万–19.4 万步），所有臂在同一评测网格上配对。

| 臂 | 回报 终点 | 回报 尾段均值 | 回报 最佳 | 胜率 尾段均值 |
|---|---|---|---|---|
| `nocql` | 6.77 / 7.03 / 7.15 | 6.58 / 7.05 / 6.70 | 12.815 | 0.000 |
| `uniform` | 9.07 / 8.76 / 9.01 | 8.99 / 8.85 / 9.08 | 12.815 | 0.000 |
| `gated` | 9.08 / 9.15 / 8.82 | 9.36 / 9.09 / 8.88 | 12.815 | 0.021 |
| `anti` | 9.80 / 9.98 / 9.37 | 9.98 / 9.85 / 9.20 | 12.815 | 0.073 |

关键读数：

- **保守项通道整体有效**：`uniform − nocql` 尾段均值 **+2.199**，3/3 seed 为正（[2.417, 1.798, 2.381]）。
- **预登记的队友支持放置不成立**：`gated − uniform` 尾段均值 **+0.135**，3/3 seed 中仅 2/3 为正（[0.363, 0.241, −0.199]），未达预先登记的通过标准。
- **反向放置反而略好**：`anti − uniform` 尾段均值 **+0.395**，3/3 seed 为正（[0.422, 0.884, 0.318]）；终点 **+0.472**（[0.460, 0.644, 0.312]）。

## 3. 预先登记判读

阶段 C 报告第 8 节提出阶段 D 的判读：

- 若 `gated > uniform` 且 `gated > anti`，方向跨 seed 一致 → 队友支持放置机制成立。
- 否则，收益来自保守项总量本身，放置方式无显著差异。

实际结果触发**第二条分支**：保守项总量本身带来 +2.20 的收益，但按队友支持度放置没有稳定优势；`anti` 略好但幅度不大（尾段均值 +0.40，约为 `uniform − nocql` 的 18%）。

## 4. 对 `anti` 略好的解释

`anti` 把惩罚放在老队支持度低的步，即当前策略正在探索离线数据没怎么见过的联合动作的位置。这等价于在"分布外"的在线样本上集中保守惩罚，而 `gated` 则把惩罚集中在"分布内"样本上。

这一结果与阶段 A 的代理口径并不矛盾：阶段 A 测得"离线价值主张失真最小"的样本正是老队支持度高的样本；对这类样本少罚、对老队未见过的样本多罚，是更自然的保守项放置。阶段 A 的冠军信号 `tm_logp_h1` 回答的是"哪里离线价值还准"，而 CQL 惩罚应当放在"哪里离线价值不准且可能过估计"的地方——二者方向相反。

## 5. 与阶段 C 的对比

| 通道 | 队友条件假设 | 结果 | 关键比较 |
|---|---|---|---|
| 价值记忆（floor） | 在老队支持高的步保留离线价值 | 放弃，整体负向 | `none` 显著优于所有 OVM 臂 |
| 保守项加权 | 在老队支持高的步多罚 | 不成立，总量效应为主 | `uniform − nocql` +2.20，`gated − uniform` +0.14 |

阶段 C 的失败不是信号本身的问题（阶段 A 已验证队友支持度信号真实且特异），而是价值 floor 通道存在结构性混淆：门控位置与下界幅度不可分离。阶段 D 的通道没有这一混淆，因此结果更干净：保守项总量有效，但具体放置方式的优势较小，`anti` 方向略好。

## 6. 结论

1. **保守项通道有效**。在线阶段施加全局 CQL 惩罚（`uniform`）比不加（`nocql`）在 3/3 seed 上稳定提升约 +2.20 尾段回报。
2. **队友支持度门控的 `gated` 放置未通过预注册检验**。`gated − uniform` 为 +0.135，仅 2/3 seed 为正，不能宣称机制成立。
3. **`anti` 放置（惩罚老队支持低的步）略好**，+0.40 尾段均值 / +0.47 终点，3/3 seed 一致。这提示保守项应更多放在当前策略偏离离线分布的位置，而不是老队最支持的联合动作上。
4. **机制级结论**：阶段 A 验证的队友支持度信号本身仍然成立；但在训练层，它更适合用来决定"在哪里施加保守惩罚"，且方向是反的（惩罚低支持区域）。直接用它来决定"在哪里保留离线价值"已被阶段 C 证伪。

## 7. 下一步

阶段 E 用现有 Stage D 日志做低方差一阶量验证：把 `q_overestimate_rate` 与 `q_bias` 按离线支持度偏离 `D` 分箱，比较 `gated` 与 `anti` 是否在高 `D` 区域产生不同的过估计抑制。若 `anti` 在高 `D` 区域显著降低过估计，则可以把机制明确表述为"在低队友支持区域集中保守惩罚"；若该一阶信号不存在，则报告收益可能来自权重分布的次要效应，建议收敛到更简单的全局 `online_cql_weight`。
